## 需求背景

基于 @/openspec/changes/add-main-content-base-info，需要在 BaseInfo 区域新增 Custom Index 弹窗。

## 需求描述

- 基本规则：Seller Index 满分 100 分，包含 5 个维度与 15 个具体指标，必须同时记录指标与维度的得分；另有单独的“平台扣分”维度，扣分数值由运营在管理后台配置，不计入 5 个维度得分，而是直接从总分中扣除，扣分没有上限。
- 数据处理原则：所有用于计算的源数据按照“四舍五入”处理；具体指标分数最多保留 1 位小数（与历史保持一致）；5 个维度得分以及最终总分保留 2 位小数。总分等于 5 个维度得分之和，而不是指标分数之和。

1. 点击 BaseInfo 中的 Custom Index 模块时弹出对话框。
2. 弹窗内容包含：
   - 标题：Custom Index。
   - 副标题示例：Custom Index: 77.52/100.00 最近更新时间 2025-06-16（每月 1 号和 16 号更新）。
   - 主体分为左右两栏：左侧为包含 5 个维度（产品能力、店铺维护、服务质量、商家信誉、交易经验）的雷达图；右侧为列表，展示各维度的权重与得分（如产品能力 35、店铺维护 5、交易经验 30、服务质量 15、商家信誉 15）以及平台扣分。
   - 右侧列表的每个项目都要包含：图标、指标名称、得分/扣分（平台扣分只显示负值）、CTA 区域。当存在优化建议时显示“n 项优化建议”，无建议时显示“此项表现良好”。平台扣分无总分展示，只显示扣分分值与“查看详情”操作。
   - 点击“优化建议”按钮后，在该列表项下方展开建议内容，并显示提示文案：“优化过后的项目可关注下次 Custom Index 分数更新。” 同时提供帮助中心的 Custom Index 文档链接，点击后跳转。
3. 国际化翻译文档位置：@/Prepare/【翻译文档】#57791 seller index优化与等级体系.xlsx 中20行-78行，列名中文对应的是中文翻译，列名为最终版对应的是英文翻译

### 开发规范

1. 严格遵循 openspec/project.md 的约定。
2. UI 实现前必须使用 figma MCP get_design_context + get_screenshot 获取对应节点，实现 1:1 还原。
3. 通过 superpowers-codex 加载个人 skill，完成组件开发与 mock 数据接入。
4. 组件保持最小粒度，禁止不必要的封装，确保低耦合、高可维护。

### i18n 规范

1. 阅读并遵循 https://vue-i18n.intlify.dev/。
2. 采用扁平化 key（以 . 分隔），不要在 JSON 中嵌套对象。
3. 区分单复数，可使用 \_one、\_other 后缀。
4. build 阶段扁平 key 会转换为嵌套对象，避免出现会与上级 key 冲突的命名（如 exif.custom.rendered vs exif.custom.rendered.custom）。
5. locales 位于仓库apps/web目录下，新增 key 需要同步所有语言。
6. 必须先修改 locales/en.json，再同步 zh-CN.json 以及其他语言文件，否则 eslint 会清理掉未在 en.json 中出现的 key。
